## Executive Summary

`mcp-chrome` is a monorepo project providing a bridge between Model Context Protocol (MCP) clients (such as Claude Code, Claude Desktop, Cursor, Hermes) and Google Chrome. It allows AI agents to inspect, control, automate, and extract data from a user's active Chrome browser session.

The project is structured as a pnpm monorepo containing:

1. `packages/shared` (`chrome-mcp-shared`): Shared TypeScript schemas, types, constants, and MCP tool definitions (`TOOL_SCHEMAS`).
2. `app/native-server` (`mcp-chrome-bridge`): Node.js Native Messaging Host and Fastify HTTP/SSE/Streamable-HTTP server, plus a stdio proxy (`mcp-chrome-stdio`).
3. `app/chrome-extension` (`chrome-mcp-server`): Chrome Manifest V3 extension built with WXT and Vue 3, running in the browser to execute DOM manipulation, DevTools CDP commands, screenshots, and automation.
4. `packages/wasm-simd` (`@chrome-mcp/wasm-simd`): Rust/Wasm SIMD math module for vector similarity (excluded from standard Node build).

### Core Architectural Bottlenecks & Critical Defects Identified

- **MCP Transport Singleton Conflict**: `getMcpServer()` in `app/native-server/src/mcp/mcp-server.ts` returns a module-level singleton `Server`. When multiple clients connect via SSE or Streamable HTTP concurrently, calling `server.connect(transport)` on the same instance leads to connection collision, state corruption, or disconnection of prior clients.
- **`ERR_HTTP_HEADERS_SENT` in Fastify Transport Layer**: `app/native-server/src/server/index.ts` mixes Fastify's reply lifecycle with direct Node.js raw stream manipulation (`reply.raw.writeHead`, `reply.raw.setHeader`, `reply.raw.flushHeaders`, `reply.hijack()`), leading to race conditions where error handlers or Fastify interceptors attempt to send headers after they have already been flushed.
- **Stdio Zombie Processes**: `app/native-server/src/mcp/mcp-server-stdio.ts` connects to `process.stdin` via `StdioServerTransport` and proxies calls to `http://127.0.0.1:12306/mcp`. It lacks listeners for `stdin.on('close')`, `stdin.on('end')`, or parent process termination signals, leaving orphan Node.js background processes when clients close.
- **Extension Handshake & "Permanent Yellow Status"**: The extension background script (`native-host.ts`) connects via `chrome.runtime.connectNative`, sends `{ type: 'start', payload: { port } }`, and marks `nativeConnectionStatus = 'connected'`. However, `serverStatus.isRunning` only transitions to `true` when `{ type: 'server_started' }` is received from the native host. In the popup UI, `connected && !isRunning` produces a persistent yellow warning dot (`bg-yellow-500`), caused by timing races, missed handshake packets, or failure to recover from background Service Worker suspension.
- **Missing MCP Safety Annotations**: None of the 27 registered MCP tools in `TOOL_SCHEMAS` contain the MCP specification annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`).
- **Absence of Browser-Use Index-Based DOM Engine**: Existing interaction tools (`chrome_computer`, `chrome_click_element`, `chrome_fill_or_select`) rely on CSS selectors, coordinate clicking, or ephemeral `ref` IDs generated by `chrome_read_page`. There is no numeric index-based DOM indexing, no viewport occlusion/containment pruning, and no batch action pipeline (`chrome_batch_actions`).
- **Monorepo Build & Typecheck Configuration Gaps**: Root `package.json` contains `"typecheck": "pnpm -r exec tsc --noEmit"` without filtering out `packages/wasm-simd` (which has no `tsconfig.json`). There is no root `test` script, and existing test coverage in `native-server` is limited to a single `GET /ping` test.

### 2.2 Transports Implementation Deep Dive

#### A. HTTP & SSE Transports (`app/native-server/src/server/index.ts`)

1. **SSE Endpoint (`/sse` & `/messages`)**:
   - `GET /sse`: Calls `reply.raw.writeHead(200, { 'Content-Type': 'text/event-stream', ... })`. Instantiates `new SSEServerTransport('/messages', reply.raw)`. Stores transport in `transportsMap.set(transport.sessionId, transport)`.
   - Then runs:
     ```ts
     const server = getMcpServer();
     await server.connect(transport);
     ```
   - `POST /messages`: Looks up `transportsMap.get(sessionId)`, delegates to `transport.handlePostMessage(req.raw, reply.raw, req.body)`.
2. **Streamable HTTP Endpoint (`/mcp`)**:
   - `POST /mcp`:
     - Checks `sessionId = request.headers['mcp-session-id']`.
     - If no `sessionId` and `isInitializeRequest(request.body)`: creates `new StreamableHTTPServerTransport({ ... })`.
     - Calls `await getMcpServer().connect(transport)`.
     - Stores `transport` in `transportsMap` upon initialization.
     - Calls `await transport.handleRequest(request.raw, reply.raw, request.body)`.
   - `GET /mcp`: Opens SSE stream for the session. Sets raw headers, calls `reply.raw.flushHeaders()`, awaits `transport.handleRequest(request.raw, reply.raw)`, and invokes `reply.hijack()`.
   - `DELETE /mcp`: Deletes session via `transport.handleRequest(request.raw, reply.raw)`.

#### B. The Root Causes of Concurrency & Crash Defects

1. **Singleton Server Collision**:
   `app/native-server/src/mcp/mcp-server.ts`:
   ```ts
   export let mcpServer: Server | null = null;
   export const getMcpServer = () => {
     if (mcpServer) return mcpServer;
     mcpServer = new Server(
       { name: 'ChromeMcpServer', version: '1.0.0' },
       { capabilities: { tools: {} } },
     );
     setupTools(mcpServer);
     return mcpServer;
   };
   ```
   In the MCP SDK, a single `Server` instance tracks an active transport connection. When multiple clients connect concurrently (e.g. Claude Code on Streamable HTTP and Hermes on SSE), calling `getMcpServer().connect(newTransport)` overrides or collides on the single server instance, breaking protocol state and dropping existing sessions.
2. **`ERR_HTTP_HEADERS_SENT`**:
   In `/mcp` GET and POST routes, when Fastify error handler triggers (`catch (error) { if (!reply.sent) reply.code(500)... }`), `reply.sent` might be false even after `reply.raw.writeHead` or `reply.raw.flushHeaders` has been called by the transport or route handler. Writing to `reply` after headers are flushed throws Node.js `ERR_HTTP_HEADERS_SENT`.
3. **Stdio Transport & Zombie Processes (`mcp-server-stdio.ts`)**:
   - `mcp-server-stdio.ts` starts `StdioServerTransport` and connects to `getStdioMcpServer()`.
   - It proxies `handleToolCall` to `http://127.0.0.1:12306/mcp` via `StreamableHTTPClientTransport`.
   - When the parent process (e.g., Claude Desktop) kills or closes its side of stdin, Node does not terminate automatically if the HTTP client socket or event loop handles remain open. There is no `process.stdin.on('end', () => process.exit(0))` or `process.stdin.on('close')`.

### 2.3 Chrome Extension & Native Host Communication

- **Protocol**: Chrome Native Messaging over standard I/O (binary length prefix: uint32 LE + JSON string).
- **Native Host Registration**:
  - Script: `app/native-server/src/scripts/register.ts` and `utils.ts`.
  - Windows Registry: `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.chromemcp.nativehost`.
  - Points to `dist/run_host.bat`, which detects `node.exe` (using `node_path.txt` or system PATH) and runs `dist/index.js`.
- **Extension Connection Management (`native-host.ts`)**:
  - Calls `chrome.runtime.connectNative('com.chromemcp.nativehost')`.
  - Sends `{ type: 'start', payload: { port: 12306 } }`.
  - Waits for `{ type: 'server_started', payload: { port } }`.
  - **Issue**: If the connection drops or fails to start, `nativePort.onDisconnect` triggers reconnect, but during startup, `nativeConnectionStatus` is reported as `connected` while `serverStatus.isRunning` remains `false`, displaying a yellow status indicator indefinitely until manual refresh or restart.

### 3.1 Gaps Against Project Requirements (R1 & R2)

1. **Safety Annotations Missing**: None of the tools specify `readOnlyHint`, `destructiveHint`, `idempotentHint`.
   - Read-only tools (e.g. `get_windows_and_tabs`, `chrome_read_page`, `chrome_screenshot`, `chrome_get_web_content`, `chrome_bookmark_search`, `chrome_console`) should have `readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`.
   - Destructive tools (e.g. `chrome_close_tabs`, `chrome_bookmark_delete`, `chrome_history` delete actions) should have `destructiveHint: true`.
2. **Missing Index-Based Action Engine**:
   - `chrome_read_page` generates hierarchical text with `ref_1`, `ref_2` but does not produce the compact numbered index list (`[1] <button> Submit`, `[2] <input> Username`) seen in `browser-use`.
   - No tool exists to directly execute `click(index)` or `fill(index, text)` without resolving selectors or complex ref lookups.
3. **No Batch Action Tool**:
   - Every single click, fill, wait, or keypress currently requires a separate MCP network roundtrip and LLM turn. A dedicated `chrome_batch_actions` tool is needed to execute an array of sequence steps atomically.
4. **Local File & File:// Protocol Issues**:
   - `file-upload.ts` uses `prepareFileFromRemote` via `forward_to_native`, but local path normalization on Windows (backslashes vs slashes) and navigation to `file://` URLs in `chrome_navigate` are currently blocked or unhandled by Chrome extension security defaults unless file URL access is explicitly managed.

## 5. Architectural Recommendations for Implementation

1. **Fix Transport Multi-Session Architecture**:
   - Refactor `app/native-server/src/mcp/mcp-server.ts` from a singleton `mcpServer` to a factory function `createMcpServerInstance()`.
   - Each incoming connection (Streamable HTTP session or SSE connection) must instantiate or bind its own MCP `Server` instance connected to its dedicated transport.
   - For shared tool dispatching, bind a shared tool handler registry rather than sharing the `Server` instance.
2. **Prevent `ERR_HTTP_HEADERS_SENT` in Fastify**:
   - Standardize request handling in `/mcp` and `/sse`. Use `reply.hijack()` immediately before handing over the raw Node HTTP socket to the MCP SDK transport.
   - Wrap raw socket writes in defensive checks (`if (!reply.raw.headersSent)`).
3. **Ensure Stdio Auto-Exit**:
   - In `app/native-server/src/mcp/mcp-server-stdio.ts`, attach listeners:
     ```ts
     process.stdin.on('close', () => process.exit(0));
     process.stdin.on('end', () => process.exit(0));
     process.on('SIGINT', () => process.exit(0));
     process.on('SIGTERM', () => process.exit(0));
     ```
   - Unref internal timers or HTTP keep-alive connections so the event loop drains naturally.
4. **Implement Browser-Use Index-Based DOM Engine**:
   - Create a dedicated DOM extractor script in `inject-scripts/` mirroring `browser-use/dom/serializer/serializer.py`.
   - Prune non-interactive elements, filter out invisible/occluded bounding boxes, and assign clean 1-based index numbers `[1], [2], ...`.
   - Expose `chrome_get_interactive_elements` / `chrome_take_dom_snapshot` and direct index action tools: `chrome_click_index(index)` and `chrome_fill_index(index, value)`.
   - Expose `chrome_batch_actions(actions: Action[])` executing sequential pipeline operations with fail-fast status.
5. **Add MCP Annotations**:
   - Update all schemas in `packages/shared/src/tools.ts` with standard MCP `annotations`:
     `readOnlyHint`, `destructiveHint`, `idempotentHint`.
6. **Fix Monorepo Build & Typecheck Scripts**:
   - Update root `package.json`:
     `"typecheck": "pnpm -r --filter='!@chrome-mcp/wasm-simd' exec tsc --noEmit"`
     `"test": "pnpm -r --filter='!@chrome-mcp/wasm-simd' test"`
   - Add unit and integration tests for MCP server multi-client connections, stdio lifecycle, and index-based actions.
